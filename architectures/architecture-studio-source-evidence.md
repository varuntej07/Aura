# Aura Voice Architecture Source Evidence

This report maps the Architecture Studio's visible voice-system claims to repository source and tests. It covers the verified registry in `app/data/architecture.ts` and the deterministic scenarios in `app/data/simulations.ts`.

This is an evidence index, not a test-run report. A cited test shows where a behavior is asserted. `QA_REPORT.md` owns the result of running the studio and repository test suites.

## How to read an anchor

- Evidence paths are relative to the Aura repository root. Studio paths beginning with `app/` are relative to `architecture-studio/`.
- A line number points to the first useful line at the time of the audit. Use the symbol when lines drift.
- Source is authoritative over comments and architecture documents.
- A test proves only the behavior named in its note. It does not prove that the component is wired into production.
- Configured values are labeled as configuration. They are not measured production latency or reliability.
- The dashboard uses deterministic local payloads. It never reads production data, logs, metrics, or secrets.

## Coverage gaps and risks not yet promoted

The following findings affect interpretation but are not all present in the visible `knownRisks` collection:

1. **Current Flutter launches resolve to App.** `HomeViewModel.startSession` at `lib/presentation/viewmodels/home_viewmodel.dart:126` creates a conversation ID and omits `surface`. The keyboard handoff at `lib/presentation/screens/home/home_screen.dart:308` uses the same launcher. Keyboard and Desktop are server-supported contracts, not current Flutter launch truth.
2. **Token prewarm usually cannot reuse its cached token.** `VoiceSessionService.startSession` at lines 151 to 165 rejects prewarmed token reuse when a conversation ID is present. `HomeViewModel` normally creates one first. Microphone prewarm still helps.
3. **MCP token failure prevents the session.** `backend/src/agent/voice_agent.py` at 363 to 379 returns before `AgentSession.start`. A nearby comment suggesting tool-less continuation is stale.
4. **The context deadline is all-or-default on aggregate timeout.** Fast values are discarded when one operation holds the shared gather to 1.5 seconds. This needs focused regression coverage.
5. **No provider chain has direct order tests or fallback activation telemetry.** The pipeline source is the only ordering authority. The top-level `backend/src/agent/voice_agent.py` docstring is stale and omits current OpenAI and Deepgram TTS fallback.
6. **Client first-response analytics can precede speech.** `lib/data/services/voice_session_service.dart` around 304 marks first response on remote audio-track subscription. First-talk waits for assistant transcript activity later.
7. **Production voice logs contain user content.** `backend/src/agent/voice/recorder.py` at 266 to 379 logs full final STT text and an assistant preview. The studio must not imply that all operational telemetry is content-free.
8. **Pre-session Aura reads have no local consent gate.** `backend/src/agent/voice/fetchers.py` at 146 reads Aura context. Post-session Aura mutation checks consent in `backend/src/services/user_aura_extractor.py` around 632 and `backend/src/services/aura_reflection.py` around 623.
9. **Post-session execution is not durable.** `backend/src/agent/voice_agent.py` at 671 to 697 creates an in-process task with no restart or queue retry guarantee.
10. **Stored model attribution can be wrong.** `backend/src/services/voice_session_summarizer.py` around 198 writes `settings.ANTHROPIC_VOICE_MODEL` regardless of the provider fallback that actually completed.
11. **Screen data sender validation is uneven.** Guide control validates participant identity, but frame and text dispatch rely on room admission and expected one-user topology.
12. **Text screen context has no timestamp freshness.** It is bounded and delivered once, but source provides no capture-age check.
13. **Guide direct control lacks a launch-surface check.** Capability exposure is Desktop-only, but inbound direct `guide.mode` control does not enforce launch surface.
14. **Guide repair can be overstated.** The runtime waits for later user input and replans. It does not autonomously manipulate the target application.
15. **Draft persistence has a contract mismatch.** The snippet event can say `persisted:false`, while the implementation still calls draft persistence.
16. **`safe_concurrently` is descriptive metadata only.** No production reader was found. Actual per-generation behavior comes from `BuddyAgent._apply_execution_safety`.
17. **Voice generic idempotency is inactive.** The MCP path constructs `ToolExecutor` without `client_message_id`. Reminder has semantic deduplication, while calendar writes do not have a generic equivalent.
